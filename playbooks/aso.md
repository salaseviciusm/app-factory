# ASO Playbook

App Store Optimization. Applied at stage 2 (keyword landscape), stage 3 (naming),
stage 8 (listing assembly), and continuously by marketing.

## Naming (stage 3)

- Pattern that works for portfolio apps: `<Brand>: <category keyword phrase>`
  (e.g. "Pace: Run Tracker & Routes"). Brand is ownable; suffix is searchable.
- Check before committing: App Store + Play search collisions, trademark scan,
  domain/social handle availability, and that the name reads well in a home-screen
  label (~11 chars visible).
- The bundle ID never changes; pick it like it's permanent (it is).

## Keyword research (stage 2)

- Mine: competitor titles/subtitles, their review vocabulary (what words do USERS use?),
  autocomplete on both stores, category top charts.
- Deliverable: primary keyword phrase (title suffix), secondary set (subtitle),
  long-tail set (iOS keyword field / Play description), each with an honest
  competitiveness note. We win long-tail first, head terms later.
- **Differentiation statement**: one sentence on why this listing won't read as another
  template app — this doubles as our Apple 4.3 defense and goes in the spec.

## Listing assembly (stage 8)

- Title ≤30 chars (iOS), subtitle ≤30: benefit + keywords, no keyword stuffing.
- Screenshots sell the one great interaction in frame 1; captions are benefit-first,
  in brand voice; device frames from the brand pack's screenshot templates.
- First 3 lines of description carry the pitch (fold line); rest is scannable feature
  blocks + social proof placeholder.
- Localize listing for top-5 markets of the category ONLY when analytics show non-EN
  traction (cheapest-viable-step rule).

## Post-launch loop (marketing)

- Weekly: keyword rank movement, conversion rate (views→installs), competitor listing
  changes worth reacting to.
- Review prompts: ask after a success moment (see analytics taxonomy `milestone-*`
  events), never on first open, never after a crash. Respond to every review ≤4 stars
  with a human-approved template in brand voice.
- Listing changes are experiments: one variable at a time, logged with hypothesis
  (screenshots first — highest leverage; icon tests only with real traffic volume).

## Cadence guardrail

Store accounts live or die on trust. 2–4 releases/month across the portfolio, every
listing genuinely differentiated, no burst-submitting near-identical apps. This
playbook is subordinate to that rule.
