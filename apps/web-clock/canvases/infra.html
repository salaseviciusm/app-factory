Runtime pipeline

High-frequency frames never hit the event log. Durable facts do. That split is load-bearing — do not “unify” them.

1. Capture

expo-camera preview. Phone upright, ¾ standing, bar + full body. No recording required for a live set.

2. Vision

Local Expo module. 2D request for squat/push-up joints. 3D request for pull-up chin-over-bar without a face.

3. PoseSource

Canonical PoseFrame. Live, simulated, or fixture replay. Vendor types die at the adapter.

4. Director

Framing gate → active detector → 5/10/15 advance → AMRAP clock. Live state in Cells.

5. Log

session / rep / reject / round / finish events. Projections fold scores and history. Persistence-first on the bus.

Two channels

Kind Mechanism Examples Do not
Live · ~15–30 Hz Cell + useSyncExternalStore remainingMs, currentExercise, repsInMove, rounds, framingOk, lastVerdict, skeleton Publish pose frames on the bus
Durable facts zod events, append-only session-started, rep-counted, rep-rejected-invalid, exercise-advanced, round-completed, session-finished Update or delete a row
Reads projections re-fold the log SessionDetail, ScoreHistory, PersonalBest Keep a mutable mirror “for speed”
Algorithms version string on every derived event pullup-v1, pushup-v1, squat-v1 Retune a frozen version in place

Domain events (proposed)

Names are category-entity-action. Schema version 1. Detector version is a payload field, not the event type.

Event When Payload (beyond envelope)
session-started framing gate green + user starts sessionId, planId=cindy-rx-20, durationMs=1200000
rep-counted active detector commits a rep sessionId, exercise, detectorVersion, romHint?
rep-rejected-invalid motion seen, standard failed or confidence low sessionId, exercise, reason, detectorVersion
exercise-advanced 5 or 10 or 15 hit sessionId, from, to, roundIndex
round-completed squat 15/15 sessionId, roundIndex
session-finished clock hits 0 or user ends sessionId, reason, scoreRounds, scoreLeftover, leftoverExercise
rep-adjusted-manual +1 / −1 sessionId, exercise, delta

Detectors — v1 contracts

State machines, not thresholds. Synthetic fixtures first; founder clips retune versions, they do not rewrite the machine. 3D hips are unusable — squats must ride 2D.

Detector Primary signal Gate Ignore
pullup-v1 3D elbow angle + head.y vs mean wrist.y usable head+wrists+elbows; undercount if gap Hips, nose, kip flourish
pushup-v1 2D elbow angle, both sides averaged shoulder–hip line roughly plank; knees not a free pass Absolute 3D calibration
squat-v1 2D hip.y oscillation + knee angle stand → depth → stand; hysteresis 3D hip/root (templated at origin)
framing-v1 min confidence on the joints the active detector needs refuses start; suspends count on drop Pretty skeleton as a success signal

PoseSource seam

LiveVisionPoseSource

iOS only. Wraps the Expo module. Maps Vision joints into canonical names. Drops frames below a floor. Composition-root line, nothing else.

SimulatedPoseSource

Ships in src (not test-only). Emits kinematic 5-10-15 cycles. Lets the HUD and director be developed on Linux / Expo web without a device.

FixtureReplaySource

Plays fixtures/*.recording.json. Tomorrow’s raw clips become goldens the same way skip-hero replays examples/*.recording.json.

Tomorrow’s footage path

Founder: the YouTube short is reference, not raw. When examples land, we do not eyeball thresholds in the Swift module. We extract, commit the pose tape, lock a golden.

.MOV

Local / Slack library. Gitignored. Provenance in a manifest.

pose-extract.swift

AVFoundation + the same Vision requests as the live module. macOS.

recording.json

Canonical frames. Committed. No pixels.

director replay

Deterministic fold. Human-verified score on the fixture.

golden

Versioned expected events. Fail the run if a retune drifts them.

Honest limit: Vision extract is Mac-only. This Linux agent can ship the Swift CLI and the TS replay; it cannot certify a golden from raw video here. That is a founder-machine step, same as skip-hero’s pose-extract.

Composition root — the only new() site

Always

newId, clock, InMemoryEventBus, persistPublishedEvents → store.

GrantAllEntitlements until RevenueCat exists.

NoopAnalytics until the PostHog adapter is a one-line swap.

WorkoutDirector subscribed to PoseSource frames, publishing events.

Selected by env, not by ifs in features

EXPO_PUBLIC_POSE=live|sim|fixture

Live on device builds. Sim on web/Linux. Fixture in golden:check.

Swapping Vision for a later MediaPipe Android source is an adapter file plus one line here. That is the skip-hero compliance test.

Analytics (defined before code)

Activation: session-first-completed — first 20:00 (or early finish) with at least one verified rep. Habit: session-completed. Feature: rep-counted, rep-rejected-invalid, framing-gate-passed, score-viewed, rep-adjusted-manual.

No pose, no coordinates, no video in PostHog. Crash-free sessions stay — they are an ASO metric on Play and a quality metric everywhere.

What we refuse

No hero splash

features.onboarding.enabled = false. Camera permission is the first gate, on Start. A marketing carousel is not a feature.

No cloud pose

Frames stay on device. Analytics never sees joints. That is both privacy and the skip-hero “keypoints, not footage” rule.

No skip-hero screens

We take the pipeline, not Tile Rush, not lessons, not the cyan nocturne HUD. Crimson clock. Different sport. 4.3.

No Marvel surface

Bundle, icon, copy, tags. If Apple’s tagger emits “spider-man”, we delete the tag.

No leaderboard v1

Camera counters get 1★ for being cheatable. Manual +1 is for the athlete, not for a global rank.

No factory-run from this agent

Engine and Slack are not in this environment. These files are the spec-repo artifacts. Stamp happens after you say go.

Risks that should delay stamp

Risk Why it matters Cheapest next step
Three moves, one angle Pull-up 3D ignores hips; squat 2D needs them. Wait for tomorrow’s clips before freezing thresholds.

Cindy timers already exist Without Vision we are the third 0-rating clock. Do not stamp a tap-only MVP “to be safe.”
